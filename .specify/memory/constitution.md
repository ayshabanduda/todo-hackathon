# Todo Evolution Hackathon Constitution

<!-- 📋 Architectural decision detected: Global Constitution for SDD. Document reasoning and tradeoffs? Run `/sp.adr Global-Constitution-SDD`. -->

## Core Principles

### I. Spec-Driven Development (SDD)
This project follows strict Spec-Driven Development. Every feature, refactor, or fix must originate from a formal specification. The system architecture is defined by the human Architect, while the execution is performed by AI agents.

### II. Strict Role Separation
The human (Architect) MUST NOT write, edit, or refactor source code manually. Their role is restricted to creating or modifying specifications, plans, task definitions, and agent/skill definitions. All source code must be generated by AI agents through approved tasks.

### III. Task-Based Implementation
AI agents are authorized to create, modify, and refactor code only when the work is explicitly linked to an approved Task ID. Agents must not generate code without an approved task. The rule is: **No Task ID → No Code.**

### IV. Hierarchy of Truth (Strict)
The hierarchy of truth determines which document prevails in case of conflict:
1. Constitution (this document)
2. Specifications (`/specs/<feature>/spec.md`)
3. Plans (`/specs/<feature>/plan-template.md`)
4. Tasks (`/specs/<feature>/tasks.md`)
Agents must always follow the latest approved version of these documents. If specifications change, subsequent plans and tasks must be updated or regenerated.

### V. Auditable Execution & Traceability
Every behavior in the system must be traceable to a Task ID. Every Task ID must trace back to a specification. To maintain this traceability, all generated code must include comments referencing the relevant Task ID(s).

### VI. Constant Constitution
This constitution is global and applies to all phases of the Todo Evolution Hackathon (Phase I through Phase V). It remains constant even as technologies, storage models, and architectures evolve across phases.

## Scope & Evolution
The project will evolve through multiple phases. While the underlying technology stack or architectural patterns may shift between phases to meet new requirements, the fundamental principles of SDD and role separation are non-negotiable.

## Human (Architect) Constraints
The Human Architect is the sole source of intent. They manage the "What" and "Why" through:
- Feature Specifications
- Implementation Plans
- Task Definitions
- Agent and Skill Definitions
Direct modification of source files (`.py`, `.ts`, `.js`, etc.) by the human is a violation of this constitution.

## Governance
This constitution supersedes all other development practices in this project. All AI agent interactions must be verified against these principles. Compliance is enforced through the SpecKit Plus workflow.
